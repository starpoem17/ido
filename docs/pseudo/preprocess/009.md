# 009 전처리 스도코드 (데이터셋별 전처리 + append 통합 상세본)

## 0) 목적
`docs/plans/preprocess.md`의 확정 정책을 코드로 옮길 수 있도록 009 전용 Adapter 스도코드를 정의한다.  
핵심 전제는 다음과 같다.

1. 009는 독립 전처리 단위로 실행 가능해야 한다.
2. 다른 데이터셋(010/011/019/기타)도 같은 방식으로 각자 전처리한 뒤, 동일 Lance 저장소에 append한다.
3. 최종 통합은 "여러 데이터셋 동시 빌드"가 아니라 "데이터셋별 전처리 결과의 순차 append"로 수행한다.
4. 009는 통합 파이프라인 안에서 `FT 세션 직렬화 Adapter`로 동작한다.

---

## 1) 사용자요청확인 반영(확정값)
아래는 구현 시 그대로 하드 규칙으로 반영한다.

1. `_indices` 생성 시점  
   사용자요청확인: 모든 대상 데이터셋이 Lance에 적재된 후 1회 생성
2. `manifest-<version>.json` 버전 정책  
   사용자요청확인: 정수 증가(`v0001`, `v0002`, ...)
3. `quality_report` 상세도  
   사용자요청확인: 집계 수치 + 제외 사유별 샘플만 저장
4. 세션 마지막이 `user`로 끝나는 경우  
   사용자요청확인: 마지막 `user` 턴만 제거하고 세션은 포함
5. 장문 세션 처리  
   사용자요청확인: 1세션 1row 유지(전처리 분할 없음), 길이 제어는 학습 로더에서 수행

## 2) append 통합 파이프라인 인터페이스 계약
009는 아래 공통 계약을 만족하는 Adapter를 제공한다.

### 2.1 공통 row 스키마 계약
`CanonicalRow`:

1. `data_type: string` (`PT` 또는 `FT`)
2. `source: string`
3. `split: string` (`train|val`)
4. `content: string | null`
5. `messages: list<struct<role:string, content:string>> | null`
6. `token_count: int32`

009는 항상 `FT`만 생성한다.
- `content = null`
- `messages != null`

### 2.2 Adapter 함수 계약
`DatasetAdapter` 공통 인터페이스:

1. `adapter_name() -> string`
2. `discover_inputs() -> list<InputFile>`
3. `iter_rows() -> Iterator[CanonicalRow]`
4. `stats() -> AdapterStats`
5. `quality_events() -> Iterator[QualityEvent]`

009 구현체 이름: `Adapter009TechScienceMultiSession`

### 2.3 품질 이벤트 계약
`QualityEvent` 필드:

1. `dataset: string` (`009`)
2. `split: string`
3. `file_path: string`
4. `session_id: string|int|null`
5. `reason_code: string`
6. `reason_detail: string`
7. `sample_text: string|null`

009 reason code:
- `EMPTY_UTTERANCE`
- `UNKNOWN_ROLE`
- `STARTS_WITH_ASSISTANT`
- `ROLE_ALTERNATION_BROKEN`
- `NO_ASSISTANT_AFTER_TRIM`
- `TRAILING_USER_DROPPED` (제외 아님, 보정 이벤트)
- `TOKEN_COUNT_ERROR`
- `FILE_PARSE_ERROR`

## 4) 통합 실행 오케스트레이션(데이터셋별 전처리 후 append)
아래 함수는 데이터셋을 순차 실행하여 통합 Lance 저장소에 append한다.

```text
함수 통합_전처리_실행(run_config):
    run_id = 새_run_id_생성()
    adapter_순서 = [
        Adapter009TechScienceMultiSession(run_config),
        Adapter010(...),
        Adapter011(...),
        Adapter019(...),
        ... 필요 대상
    ]

    공통_스키마_검증_초기화()
    토크나이저 = 토크나이저_로드(run_config.tokenizer_json)
    manifest_집계기 = ManifestAccumulator()
    quality_집계기 = QualityAccumulator()
    lance_writer = LanceAppendWriter(path=data/korean_processed/chunks, target_bytes=1GiB)

    for adapter in adapter_순서:
        dataset_row_count = 0
        dataset_quality_count = 0

        for row in adapter.iter_rows():
            공통_스키마_검증(row)
            lance_writer.append(row)             # 기존 통합 Lance에 append
            manifest_집계기.add_row(row)
            dataset_row_count += 1

        for ev in adapter.quality_events():
            quality_집계기.add(ev)
            dataset_quality_count += 1

        manifest_집계기.add_adapter_stats(adapter.stats())
        로그기록(adapter.adapter_name(), dataset_row_count, dataset_quality_count)

    chunk_meta = lance_writer.finalize()
    manifest = manifest_생성(run_id, chunk_meta, manifest_집계기, run_config.tokenizer_id)
    quality_report = quality_report_생성(run_id, quality_집계기)   # 집계 + 샘플
    manifest_저장(manifest)
    quality_report_저장(quality_report)

    indices_생성()  # 모든 대상 데이터셋 append 완료 후 1회 실행
```

## 5) 009 Adapter 상세 절차
### 5.1 입력 파일 탐색
`discover_inputs()`:

1. `TRAIN_INPUT_GLOB`, `VAL_INPUT_GLOB` 각각 glob 탐색
2. 경로 정렬(재현성 보장)
3. `InputFile{path, split}` 리스트 반환

### 5.2 row 생성 메인 루프
`iter_rows()`:

```text
함수 iter_rows():
    for input_file in discover_inputs():
        json_obj = 파일_파싱(input_file.path)
        if 파싱실패:
            quality_event(FILE_PARSE_ERROR) 기록
            continue

        sessions = session_배열_추출(json_obj)
        if sessions 누락:
            quality_event(FILE_PARSE_ERROR, detail="sessionInfo 누락") 기록
            continue

        for session in sessions:
            결과 = 세션_정규화(session, input_file)
            if 결과.status == "emit":
                yield 결과.row
            else:
                continue
```

### 5.3 세션 정규화(핵심)
`세션_정규화(session, input_file)`:

```text
입력:
    session: 원본 세션 객체
    input_file: {path, split}
출력:
    {"status":"emit","row":CanonicalRow} 또는 {"status":"skip"}

절차:
1) dialog 추출
   dialog = session["dialog"] (없으면 skip + FILE_PARSE_ERROR)

2) turn 정리
   turns = []
   for raw_turn in dialog (원순서):
       raw_speaker = raw_turn.speaker
       text = raw_turn.text.strip()
       if text == "":
           quality_event(EMPTY_UTTERANCE) 기록
           return skip

       if raw_speaker == "speaker1":
           role = "user"
       elif raw_speaker == "speaker2":
           role = "assistant"
       else:
           quality_event(UNKNOWN_ROLE) 기록
           return skip

       turns.append({"role": role, "content": text})

3) 시작 role 검증
   if turns 비어있음:
       quality_event(NO_ASSISTANT_AFTER_TRIM) 기록
       return skip
   if turns[0].role != "user":
       quality_event(STARTS_WITH_ASSISTANT) 기록
       return skip

4) role 교대 검증
   for i in 1..len(turns)-1:
       if turns[i].role == turns[i-1].role:
           quality_event(ROLE_ALTERNATION_BROKEN) 기록
           return skip

5) 마지막 user 보정(사용자 확정값)
   if turns[-1].role == "user":
       dropped_turn = turns.pop()
       quality_event(TRAILING_USER_DROPPED, sample=dropped_turn.content[:QUALITY_SAMPLE_TEXT_MAX_CHARS]) 기록

6) 보정 후 유효성 검증
   if turns 비어있음:
       quality_event(NO_ASSISTANT_AFTER_TRIM) 기록
       return skip
   if turns[-1].role != "assistant":
       quality_event(NO_ASSISTANT_AFTER_TRIM) 기록
       return skip
   if assistant 턴 개수 == 0:
       quality_event(NO_ASSISTANT_AFTER_TRIM) 기록
       return skip

7) messages 구성
   messages = []
   messages.append({"role":"system","content":SYSTEM_PROMPT})
   for t in turns:
       messages.append({"role":t.role, "content":t.content})

8) token_count 계산
   tc = 토큰수_계산(messages)
   if tc 계산 실패:
       quality_event(reason_code="TOKEN_COUNT_ERROR") 기록
       return skip

9) CanonicalRow 생성
   row = {
       "data_type": "FT",
       "source": SOURCE,
       "split": input_file.split,
       "content": null,
       "messages": messages,
       "token_count": tc
   }
   return emit(row)
```

## 6) token_count 계산 스도코드
`토큰수_계산(messages)`:

```text
전역 tokenizer는 실행 시작 시 1회 로드한다.

함수 토큰수_계산(messages):
    texts = []
    for m in messages:
        texts.append(m.content)

    # 전처리 단계에서는 특수 토큰을 삽입하지 않는다.
    joined = "\n".join(texts)
    ids = tokenizer.encode(joined).ids
    n = len(ids)

    if n > INT32_MAX:
        raise OverflowError
    return int32(n)
```

주의:
1. 009 전용 토크나이저 분기 금지(공통 토크나이저만 사용)
2. 특수 토큰(`<|system|>` 등)은 학습 로더에서 붙인다(전처리에서 미삽입)

## 7) DuckDB/Arrow 공통화 단계(통합 코드 친화)
009 Adapter는 row를 바로 Lance에 쓰지 않는다.  
반드시 공통 캐노니컬 검증 레이어를 거친다.

1. `DuckDB` 임시 relation 적재
- 컬럼 6개를 고정 타입으로 적재
- split 허용값 검사(`train|val`)
- FT/PT 상호배타 규칙 검사

2. `Arrow` 변환
- relation -> RecordBatch 변환
- 공통 schema 캐스팅 실패 시 run 중단 여부 정책 적용

3. 공통 writer 입력
- Arrow batch 또는 row iterator를 `LanceAppendWriter`에 전달

## 8) Lance append 규칙
`LanceAppendWriter`:

1. 입력은 모든 Adapter의 공통 row 스트림
2. `target_bytes = 1GiB`
3. 행 원자성 보장(행 중간 분할 금지)
4. 임계 초과 시 “방금 추가한 row 포함”으로 chunk 마감
5. chunk 이름은 전역 증가 id 사용(`chunk-000001.lance`, ...)
6. 데이터셋별 개별 Lance를 만들지 않고, 동일 통합 Lance 경로에 append한다.
7. 첫 append 시 저장소가 없으면 생성(create), 이후는 append 모드로 연다.
8. 데이터셋 경계로 chunk를 강제 마감하지 않는다(바이트 기준 마감 우선).

## 10) 완료 검증 체크리스트
1. 출력 row 전부가 공통 6컬럼 스키마와 타입에 일치하는가
2. 009 row가 FT 규칙(`content=null`, `messages!=null`)을 만족하는가
3. 009 `messages`가 `system`으로 시작하는가
4. system 이후 role이 `user/assistant` 교대를 만족하는가
5. 마지막 role이 `assistant`인가(마지막 `user` 보정 후)
6. `TRAILING_USER_DROPPED` 건수가 quality report에 집계되는가
7. 전체 chunk row 합 = manifest 전체 row 수인가
8. `_indices`가 전체 데이터 적재 완료 후 1회만 생성되었는가
9. 데이터셋 처리 순서가 달라도 append 후 schema 일관성이 유지되는가

---

## 11) 실패 처리 정책
1. 토크나이저 로드 실패: 즉시 중단
2. 스키마 불일치(공통 계약 위반): 즉시 중단
3. 파일 파싱 실패: 파일 스킵 + 품질 이벤트 기록(임계치 초과 시 중단)
4. token_count 실패: 해당 row 스킵 + 품질 이벤트 기록(임계치 초과 시 중단)
5. chunk 저장 실패: 즉시 중단, run 상태 실패 기록

## 12) 통합 구현 메모
1. 009는 “세션을 정규화해서 CanonicalRow를 생성”하는 Adapter 책임만 가진다.
2. Lance 저장, manifest, quality report, indices는 공통 오케스트레이터가 담당한다.
3. 새 데이터셋은 "전처리 Adapter 추가 -> 같은 통합 Lance에 append" 방식으로 확장한다.
