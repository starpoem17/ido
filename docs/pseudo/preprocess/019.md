# 019 전처리 의사코드

## 목적
이 문서는 `019.법률, 규정 (판결서, 약관 등) 텍스트 분석 데이터`를 `docs/personal/preprocess/019.md`의 예시 형태 그대로 Lance row로 만드는 절차를 자연어로 설명한다.
이 데이터셋에서 Lance에 저장되는 row는 PT용 `content`만 가지며, `messages`는 항상 `null`이다.

## 고정값
구현할 때는 아래 값을 그대로 사용한다.

1. `source`는 `"019.법률, 규정 (판결서, 약관 등) 텍스트 분석 데이터"`로 둔다.
2. train 입력은 `data/korean_raw/019.법률, 규정 (판결서, 약관 등) 텍스트 분석 데이터/01.데이터/1.Training/라벨링데이터_230510_add/**/*.json`에서 찾는다.
3. val 입력은 `data/korean_raw/019.법률, 규정 (판결서, 약관 등) 텍스트 분석 데이터/01.데이터/2.Validation/라벨링데이터_230510_add/**/*.json`에서 찾는다.
4. `split`은 경로 기준으로 `train`, `val`만 사용한다.
5. content 결합 구분자는 줄바꿈 `\n` 하나로 둔다.

## 입력 파일 탐색 절차
구현할 때는 아래 순서를 따른다.

1. train glob으로 파일을 모두 찾는다.
2. 파일 경로를 정렬한다.
3. 각 파일에 `split="train"`을 붙인다.
4. val glob으로 파일을 모두 찾는다.
5. 파일 경로를 정렬한다.
6. 각 파일에 `split="val"`을 붙인다.
7. 두 목록을 합쳐 입력 파일 목록으로 사용한다.

## 파일 처리 절차
파일 하나를 처리할 때는 아래 순서를 따른다.

1. JSON 파일을 읽는다.
2. 파싱에 실패하면 파일 단위 품질 이벤트를 남기고 다음 파일로 넘어간다.
3. 아래 8개 후보 필드를 순서대로 읽는다.
4. `mentionedItems.rqestObjet`
5. `disposal.disposalcontent`
6. `assrs.dedatAssrs`
7. `facts.bsisFacts`
8. `dcss.courtDcss`
9. `close.cnclsns`
10. `clauseArticle`
11. `comProvision`

## PT content 추출 절차
레코드 하나를 PT content로 바꿀 때는 아래 순서를 따른다.

1. 결과 문장 버퍼를 빈 배열로 시작한다.
2. 각 대상 필드가 배열인지 확인한다.
3. 배열이 아니면 해당 필드만 제외하고 `skip_field` 이벤트를 남긴 뒤 다음 필드로 진행한다.
4. 배열인 경우 원소를 처음부터 끝까지 순회한다.
5. 원소가 문자열이면 좌우 공백을 제거한다.
6. 좌우 공백 제거 후 빈 문자열이 아니면 결과 버퍼에 넣는다.
7. 문자열이 아니거나 strip 후 빈 문자열이 되면 해당 원소만 제외하고 `skip_item` 이벤트를 남긴다.
8. 일부 필드가 비어 있어도 다른 필드에서 유효 문자열이 있으면 그 문자열들만 사용한다.
9. 8개 후보 필드를 모두 처리한 뒤 결과 버퍼를 줄바꿈 `\n` 하나로 이어 붙인다.
10. 최종 문자열이 비어 있지 않으면 row를 생성하고, 그 과정에서 기록된 `skip_field`와 `skip_item`은 `fixup`으로 남긴다.
11. 최종 문자열이 비어 있을 때만 이 레코드를 버리고 `empty_content` 이벤트를 `skip`으로 남긴다.

## row 생성 절차
정규화에 성공한 레코드는 아래 형태의 row 하나를 만든다.

1. `source`는 고정값을 넣는다.
2. `split`은 입력 파일에서 가져온 값을 넣는다.
3. `content`에는 `PT content 추출 절차`의 결과 문자열을 넣는다.
4. `messages`는 `null`로 둔다.
5. `token_count`는 저장 직전에 `content` 문자열 기준으로 계산한다.

## PT 사용 전략
이 데이터셋은 PT 전용으로 사용한다.

1. PT 학습 시 row의 `content`를 그대로 사용한다.
2. FT 학습에서는 이 데이터셋 row를 사용하지 않는다.

## 품질 이벤트 기록 방식
품질 이벤트를 남길 때는 최소한 아래 정보를 기록한다.

1. dataset은 `019`
2. split
3. file path
4. case id(`info.caseNo` 또는 파일명)
5. reason code
6. reason detail
7. sample text 일부
8. `skip`, `fixup`, `error` 중 성격

## 구현 체크리스트
1. 최종 row의 `messages`가 항상 `null`인가
2. 대상 8개 후보 필드를 지정 순서대로 처리하는가
3. 일부 필드가 비어 있어도 나머지 필드만으로 row를 계속 생성하는가
4. 문자열에 strip을 적용하고 빈 문자열을 제외하는가
5. 최종 content를 `\n` 구분자로 concat하는가
6. `token_count`를 content 기준으로 계산하는가
