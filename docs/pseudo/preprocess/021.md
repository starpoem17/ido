# 021 전처리 의사코드

## 목적
이 문서는 `021.용도별 목적대화 데이터`를 `docs/personal/preprocess/021.md`의 예시 형태 그대로 Lance row로 만드는 절차를 자연어로 설명한다.
이 데이터셋에서 Lance에 저장되는 row는 `messages`와 `content`를 함께 가지며, `FT`와 `PT` 학습은 같은 row를 서로 다른 필드로 사용한다.

## 고정값
구현할 때는 아래 값을 그대로 사용한다.

1. `source`는 `"021.용도별 목적대화 데이터"`로 둔다.
2. system 문장은 `"당신은 콜센터 상담원입니다. 사용자의 문의에 정확하고 친절하게 답변하세요."`로 둔다.
3. train 입력은 `data/korean_raw/021.용도별 목적대화 데이터/01.데이터/1.Training/라벨링데이터/**/*.json`에서 찾는다.
4. val 입력은 `data/korean_raw/021.용도별 목적대화 데이터/01.데이터/2.Validation/라벨링데이터/**/*.json`에서 찾는다.
5. `split`은 경로 기준으로 `train`, `val`만 사용한다.
6. `data_type`은 `"dialog"`로 둔다.
7. turn 병합 구분자는 공백 하나(`" "`)로 둔다.

## 입력 파일 탐색 절차
구현할 때는 아래 순서를 따른다.

1. train glob으로 파일을 모두 찾는다.
2. 파일 경로를 정렬한다.
3. 각 파일에 `split="train"`을 붙인다.
4. val glob으로 파일을 모두 찾는다.
5. 파일 경로를 정렬한다.
6. 각 파일에 `split="val"`을 붙인다.
7. 두 목록을 합쳐 입력 파일 목록으로 사용한다.

## 파일 처리 절차
파일 하나를 처리할 때는 아래 순서를 따른다.

1. JSON 파일을 읽는다.
2. 파싱에 실패하면 파일 단위 품질 이벤트를 남기고 다음 파일로 넘어간다.
3. 최상위 `info`를 읽는다.
4. `info`가 배열이 아니면 파일 단위 품질 이벤트를 남기고 다음 파일로 넘어간다.
5. `info[*]`를 순서대로 순회하며 각 항목을 레코드 1개로 처리한다.

## 레코드 정규화 절차
레코드 하나를 row로 바꿀 때는 아래 순서를 따른다.

1. `annotations`를 읽는다.
2. `annotations.speaker_type`이 `"1:1"`인지 확인한다.
3. `"1:1"`이 아니면 이 레코드는 버리고 품질 이벤트를 남긴다.
4. PT용 원문으로 `annotations.text`를 읽는다.
5. `annotations.text`가 문자열이 아니거나 strip 후 빈 문자열이면 이 레코드는 버린다.
6. `annotations.lines`를 읽는다.
7. `lines`가 배열이 아니면 이 레코드는 버리고 품질 이벤트를 남긴다.
8. `lines`를 처음부터 끝까지 순회한다.
9. 각 line에서 `speaker.id`, `norm_text`, `text`를 읽는다.
10. `norm_text`가 문자열이면 `norm_text`를 사용한다.
11. `norm_text`가 없으면 `text`를 사용한다.
12. `text`를 사용할 때는 `"A."`, `"B."`, `"A :"`, `"B : "` 같은 화자 접두어를 제거한다.
13. 최종 turn text를 좌우 공백 제거 후 사용한다.
14. turn text가 빈 문자열이면 해당 turn은 제외하고 `skip_turn` 이벤트를 남긴다.
15. `speaker.id == "B"`면 role을 `user`로 둔다.
16. `speaker.id == "A"`면 role을 `assistant`로 둔다.
17. 그 외 speaker는 해당 turn을 제외하고 `skip_turn` 이벤트를 남긴다.
18. 정규화된 turn을 `{role, content}` 형태로 임시 배열에 넣는다.
19. 정규화 후 turn 배열이 비어 있으면 이 레코드는 버린다.

## 첫 A 제거 및 병합 절차
FT turn 배열은 아래 순서로 보정한다.

1. turn 배열에서 처음 등장한 `assistant(A)` turn 하나를 제거한다.
2. 제거 후 첫 role이 `user(B)`가 아니면 레코드를 버린다.
3. 연속으로 같은 role이 나온 turn은 `이전 content + " " + 현재 content`로 병합한다.
4. 병합 후 마지막 role이 `user`면 마지막 user turn 하나를 제거하고 `fixup` 이벤트를 남긴다.
5. 마지막 user 제거 후 배열이 비었거나 마지막 role이 `assistant`가 아니면 레코드를 버린다.
6. 최종 turn 배열에 `assistant`가 하나도 없으면 레코드를 버린다.

## row 생성 절차
정규화에 성공한 레코드는 아래 형태의 row 하나를 만든다.

1. `data_type`은 `"dialog"`로 둔다.
2. `source`는 고정값을 넣는다.
3. `split`은 입력 파일에서 가져온 값을 넣는다.
4. `messages`는 새 배열로 만든다.
5. `messages[0]`에는 고정 system 문장을 `role="system"`으로 넣는다.
6. 그 뒤에는 `첫 A 제거 및 병합 절차`를 거친 turn을 순서대로 넣는다.
7. `content`는 PT용 원문인 `annotations.text`를 strip한 문자열로 둔다.
8. `token_count`는 저장 직전에 FT 직렬화 기준으로 계산한다.

## PT 사용 전략
이 데이터셋의 PT 입력은 별도 PT row를 만들지 않고 같은 row의 `content`를 사용한다.

1. PT 학습 시 row의 `content`(`annotations.text`)를 그대로 사용한다.
2. `messages`는 PT 입력 생성에서 사용하지 않는다.

## FT 직렬화와 token_count
`token_count`를 계산할 때는 아래 순서를 따른다.

1. `messages`를 `<|system|>...<|user|>...<|assistant|>...` 형태로 직렬화한다.
2. 직렬화된 문자열을 공통 토크나이저로 인코딩한다.
3. 나온 토큰 수를 `token_count`에 넣는다.

## 품질 이벤트 기록 방식
품질 이벤트를 남길 때는 최소한 아래 정보를 기록한다.

1. dataset은 `021`
2. split
3. file path
4. record id(`info[*].id` 또는 `info[*].filename`)
5. reason code
6. reason detail
7. sample text 일부
8. `skip`, `fixup`, `error` 중 성격

## 구현 체크리스트
1. PT content가 항상 `annotations.text`에서 생성되는가
2. FT role 매핑이 `B -> user`, `A -> assistant`로 고정되는가
3. FT에서 첫 번째 `A` turn을 제거하는가
4. 제거 후 첫 turn이 `B(user)`인지 검증하는가
5. 연속 같은 화자 turn을 병합하는가
6. 마지막 user turn 보정을 수행하는가
7. `token_count`를 FT 직렬화 기준으로 계산하는가
