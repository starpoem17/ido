# 011 전처리 의사코드

## 목적
이 문서는 `011.일상대화 한국어 멀티세션 데이터`를 `docs/personal/preprocess/011.md`의 예시 형태 그대로 Lance row로 만드는 절차를 자연어로 설명한다.
이 데이터셋에서 Lance에 저장되는 row 형태는 `FT` 하나뿐이며, `content`는 항상 `null`이다.

## 고정값
구현할 때는 아래 값을 그대로 사용한다.

1. `source`는 `"011.일상대화 한국어 멀티세션 데이터"`로 둔다.
2. system 문장은 `"당신은 사용자의 대화 상대로서 친절하고 긍정적으로 반응합니다."`로 둔다.
3. train 입력은 `data/korean_raw/011.일상대화 한국어 멀티세션 데이터/3.개방데이터/1.데이터/Training/02.라벨링데이터/*.json`에서 찾는다.
4. val 입력은 `data/korean_raw/011.일상대화 한국어 멀티세션 데이터/3.개방데이터/1.데이터/Validation/02.라벨링데이터/*.json`에서 찾는다.

## 입력 파일 탐색 절차
파일 탐색은 009와 동일하게 처리하되, 경로만 011로 바꾼다.

1. train 파일을 찾고 정렬한 뒤 `split="train"`을 붙인다.
2. val 파일을 찾고 정렬한 뒤 `split="val"`을 붙인다.
3. 두 목록을 합쳐 순서대로 처리한다.

## 세션 정규화 절차
세션 정규화는 009와 같은 규칙을 그대로 사용한다.

1. `dialog[*].utterance`를 읽는다.
2. `utterance`는 좌우 공백을 제거한다.
3. 빈 발화가 하나라도 있으면 세션 전체를 버린다.
4. `speaker1`은 `user`, `speaker2`는 `assistant`로 매핑한다.
5. 첫 role이 `user`가 아니면 세션 전체를 버린다.
6. role 교대가 깨지면 세션 전체를 버린다.
7. 마지막 role이 `user`이면 마지막 turn 하나만 제거하고 `fixup` 이벤트를 남긴다.
8. 보정 후 마지막 role이 `assistant`가 아니거나 assistant turn이 없으면 세션 전체를 버린다.

## row 생성 절차
정규화에 성공한 세션은 아래 형태의 row 하나만 만든다.

1. `data_type`은 `"FT"`로 둔다.
2. `source`는 고정값을 넣는다.
3. `split`은 파일 경로 기준으로 넣는다.
4. `content`는 `null`로 둔다.
5. `messages`의 첫 원소에는 system 문장을 넣는다.
6. 그 뒤에는 정규화된 turn을 순서대로 넣는다.
7. `token_count`는 저장 직전에 FT 직렬화 기준으로 계산한다.

## PT 사용 전략
personal 문서의 `PT와 FT 시 사용 전략은 009와 동일` 규칙은 저장 row를 PT로 하나 더 만들라는 뜻이 아니라,
저장된 `FT` row를 downstream에서 어떻게 PT 문자열로 사용할지에 대한 규칙으로 해석한다.

구현할 때는 아래 helper를 별도로 둔다.

1. system 문장은 제외한다.
2. `messages`에서 user와 assistant의 `content`만 꺼낸다.
3. 원순서대로 공백 하나로 이어 붙인다.
4. 이 문자열을 PT 학습 입력으로 사용한다.

## FT 직렬화와 token_count
`token_count`를 계산할 때는 아래 순서를 따른다.

1. `messages`를 `<|system|>...<|user|>...<|assistant|>...` 형태로 직렬화한다.
2. 직렬화된 문자열을 공통 토크나이저로 인코딩한다.
3. 나온 토큰 수를 `token_count`에 넣는다.

## 품질 이벤트 기록 방식
품질 이벤트에는 최소한 아래를 남긴다.

1. dataset은 `011`
2. split
3. file path
4. session id
5. reason code
6. reason detail
7. sample text 일부
8. `skip`, `fixup`, `error`

## 구현 체크리스트
1. 최종 row가 항상 `FT`인가
2. 최종 row의 `content`가 항상 `null`인가
3. system 문구가 personal 문서와 완전히 같은가
4. `PT 시 사용 전략`을 별도 helper로 분리했는가
5. `token_count`를 FT 직렬화 기준으로 계산하는가
