# 011 전처리 의사코드

## 목적
이 문서는 `011.일상대화 한국어 멀티세션 데이터`를 `docs/personal/preprocess/011.md`의 예시 형태 그대로 Lance row로 만드는 절차를 자연어로 설명한다.
이 데이터셋에서 Lance에 저장되는 row는 `messages`와 `content`를 함께 가지며, FT와 PT 학습은 같은 row를 서로 다른 필드로 사용한다.

## 고정값
구현할 때는 아래 값을 그대로 사용한다.

1. `source`는 `"011.일상대화 한국어 멀티세션 데이터"`로 둔다.
2. system 문장은 `"당신은 사용자의 대화 상대로서 친절하고 긍정적으로 반응합니다."`로 둔다.
3. train 입력은 `data/korean_raw/011.일상대화 한국어 멀티세션 데이터/3.개방데이터/1.데이터/Training/02.라벨링데이터/*.json`에서 찾는다.
4. val 입력은 `data/korean_raw/011.일상대화 한국어 멀티세션 데이터/3.개방데이터/1.데이터/Validation/02.라벨링데이터/*.json`에서 찾는다.
5. `split`은 경로 기준으로 `train`, `val`만 사용한다.

## 입력 파일 탐색 절차
구현할 때는 아래 순서를 따른다.

1. train 파일을 찾고 정렬한 뒤 `split="train"`을 붙인다.
2. val 파일을 찾고 정렬한 뒤 `split="val"`을 붙인다.
3. 두 목록을 합쳐 순서대로 처리한다.

## 세션 정규화 절차
세션 하나를 row로 바꿀 때는 아래 순서를 따른다.

1. 세션에서 `sessionID`와 `dialog`를 읽는다.
2. `dialog`가 없거나 배열이 아니면 세션 전체를 버리고 품질 이벤트를 남긴다.
3. `dialog[*].speaker`, `dialog[*].utterance`를 순서대로 읽는다.
4. `utterance`가 문자열이 아니면 세션 전체를 버린다.
5. `utterance`는 좌우 공백을 제거한다.
6. 빈 문자열 발화가 하나라도 있으면 세션 전체를 버린다.
7. `speaker1`은 `user`, `speaker2`는 `assistant`로 매핑한다.
8. 그 외 speaker가 나오면 세션 전체를 버린다.
9. 정규화된 turn 배열이 비어 있으면 세션 전체를 버린다.
10. 첫 role이 `user`가 아니면 세션 전체를 버린다.
11. role 교대가 깨지면 세션 전체를 버린다.
12. 마지막 role이 `user`이면 마지막 turn 하나만 제거하고 `fixup` 이벤트를 남긴다.
13. 보정 후 turn이 비었거나 마지막 role이 `assistant`가 아니면 세션 전체를 버린다.
14. assistant turn이 하나도 없으면 세션 전체를 버린다.

## row 생성 절차
정규화에 성공한 세션은 아래 형태의 row 하나를 만든다.

1. `source`는 고정값을 넣는다.
2. `split`은 파일 경로 기준으로 넣는다.
3. `messages`의 첫 원소에는 system 문장을 넣는다.
4. 그 뒤에는 정규화된 turn을 순서대로 넣는다.
5. `content`는 system을 제외한 user/assistant의 `content`를 원순서대로 공백 하나로 이어 붙인 문자열로 둔다.
6. `token_count`는 저장 직전에 FT 직렬화 기준으로 계산한다.

## PT 사용 전략
이 데이터셋의 PT 입력은 별도 PT row를 만들지 않고 같은 row의 `content`를 사용한다.

1. PT 학습 시 row의 `content`를 그대로 사용한다.
2. `messages`는 PT 입력 생성에서 사용하지 않는다.

## FT 직렬화와 token_count
`token_count`를 계산할 때는 아래 순서를 따른다.

1. `messages`를 `<|system|>...<|user|>...<|assistant|>...` 형태로 직렬화한다.
2. 직렬화된 문자열을 공통 토크나이저로 인코딩한다.
3. 나온 토큰 수를 `token_count`에 넣는다.

## 품질 이벤트 기록 방식
품질 이벤트에는 최소한 아래를 남긴다.

1. dataset은 `011`
2. split
3. file path
4. session id
5. reason code
6. reason detail
7. sample text 일부
8. `skip`, `fixup`, `error`

## 구현 체크리스트
1. system 문구가 personal 문서와 완전히 같은가
2. `messages`가 `[system, user, assistant, ...]` 순서를 가지는가
3. `content`가 system 제외 user/assistant concat 규칙으로 생성되는가
4. 마지막 `user` 보정을 수행하는가
5. `token_count`를 FT 직렬화 기준으로 계산하는가
