# 국립국어원 구어 말뭉치 전처리 의사코드

## 목적
이 문서는 `국립국어원 구어 말뭉치`를 `docs/personal/preprocess/국립국어원 구어 말뭉치.md`의 예시 형태 그대로 Lance row로 만드는 절차를 자연어로 설명한다.
이 데이터셋에서 Lance에 저장되는 row는 PT용 `content`만 가지며, `messages`는 항상 `null`이다.

## 고정값
구현할 때는 아래 값을 그대로 사용한다.

1. `source`는 `"국립국어원 구어 말뭉치"`로 둔다.
2. 입력은 원본 디렉터리 아래 `*.json` 전체에서 찾는다.
3. 파일 경로는 안정적인 순서로 정렬해서 처리한다.
4. 발화 결합 구분자는 줄바꿈 `\n` 하나로 둔다.
5. split은 유효 `document` 후보 전체를 기준으로 `train:val = 90:10` self-split 한다.
6. canonical split key는 `document.id`, 없으면 `{file_stem}:{document_index}`를 사용한다.
7. split 할당은 `sha256(source + "\t" + split_key)` 기준 정렬 후 앞 `floor(n * 0.9)`개를 train, 나머지를 val로 둔다.
8. `n == 1`이면 유일한 row는 train으로 둔다.

## 입력 파일 탐색 절차
구현할 때는 아래 순서를 따른다.

1. 입력 root 아래의 `*.json` 파일을 모두 찾는다.
2. 파일 경로를 정렬한다.
3. 정렬된 순서대로 파일을 하나씩 처리한다.

## split 구성 절차
구현할 때는 아래 순서를 따른다.

1. 모든 파일을 1차 순회하며 유효 `document` 후보만 수집한다.
2. 각 후보마다 canonical split key를 만든다.
3. split key와 source를 합쳐 stable hash를 계산한다.
4. `(hash, split_key)` 오름차순으로 후보를 정렬한다.
5. 총 후보 수를 `n`으로 둔다.
6. `n == 1`이면 그 후보는 train으로 둔다.
7. `n >= 2`이면 앞 `floor(n * 0.9)`개는 train, 나머지는 val로 둔다.
8. 2차 순회에서 현재 split에 배정된 key만 실제 row로 만든다.

## 파일 처리 절차
파일 하나를 처리할 때는 아래 순서를 따른다.

1. JSON 파일을 읽는다.
2. 파싱에 실패하면 파일 단위 품질 이벤트를 남기고 다음 파일로 넘어간다.
3. 최상위 `document`를 읽는다.
4. `document`가 없거나 배열이 아니면 파일 단위 품질 이벤트를 남기고 다음 파일로 넘어간다.
5. `document` 배열을 처음부터 끝까지 순회한다.
6. `document[*]` 발화 묶음 하나를 row 후보 1개로 본다.

## document 정규화 절차
`document[*]` 하나를 row로 바꿀 때는 아래 순서를 따른다.

1. 현재 `document`에서 `id`, `metadata`, `utterance`를 읽는다.
2. `utterance`가 없거나 배열이 아니면 이 `document`를 버리고 품질 이벤트를 남긴다.
3. 유효 발화 버퍼를 빈 배열로 시작한다.
4. `utterance[*].form`를 순서대로 읽는다.
5. 현재 `utterance`가 객체가 아니면 해당 발화만 제외하고 `skip_utterance` 이벤트를 남긴다.
6. `form`이 문자열이 아니면 해당 발화만 제외하고 `skip_utterance` 이벤트를 남긴다.
7. `form`이 문자열이면 좌우 공백을 제거한다.
8. strip 후 빈 문자열이면 해당 발화만 제외하고 `skip_utterance` 이벤트를 남긴다.
9. strip 후 빈 문자열이 아니면 유효 발화 버퍼에 넣는다.
10. 유효 발화 버퍼가 비어 있으면 이 `document`를 버리고 `empty_utterances` 이벤트를 남긴다.
11. 유효 발화 버퍼를 줄바꿈 `\n` 하나로 이어 붙여 최종 `content` 문자열을 만든다.

## row 생성 절차
정규화에 성공한 `document` 하나는 아래 형태의 row 하나를 만든다.

1. `source`는 고정값을 넣는다.
2. `split`은 self-split 결과값인 `train` 또는 `val`을 넣는다.
3. `content`는 유효한 `utterance.form`들을 줄바꿈 `\n` 하나로 이어 붙인 문자열로 둔다.
4. `messages`는 `null`로 둔다.
5. `token_count`는 저장 직전에 `content` 문자열 기준으로 계산한다.

## PT 사용 전략
이 데이터셋은 PT 전용으로 사용한다.

1. PT 학습 시 row의 `content`를 그대로 사용한다.
2. FT 학습에서는 이 데이터셋 row를 사용하지 않는다.

## 제외할 메타정보
아래 필드는 기본 학습 입력에 넣지 않는다.

1. 파일 상위 `metadata`
2. `document.metadata.title`
3. `document.metadata.author`
4. `document.metadata.publisher`
5. `document.metadata.date`
6. `document.metadata.topic`
7. `document.metadata.speaker`
8. `utterance.original_form`
9. `utterance.speaker_id`
10. `utterance.note`

## 품질 이벤트 기록 방식
품질 이벤트에는 최소한 아래를 남긴다.

1. dataset은 `국립국어원 구어 말뭉치`
2. split
3. file path
4. document id 또는 document index
5. utterance index
6. reason code
7. reason detail
8. sample text 일부
9. `skip`, `fixup`, `error`

## 구현 체크리스트
1. JSON 파일 1개를 1행으로 쓰지 않고 `document[*]` 발화 묶음 1개를 1행으로 쓰는가
2. `document[*].utterance[*].form`만 사용해 `content`를 만드는가
3. 문자열에 strip을 적용하고 빈 `form`을 제외하는가
4. 발화 순서를 원본 그대로 유지하는가
5. split을 유효 `document` 후보 기준으로 정확히 90:10 self-split 하는가
6. `content`를 줄바꿈 `\n` 구분자로 결합하는가
7. `messages`가 항상 `null`인가
8. `token_count`를 `content` 기준으로 계산하는가
