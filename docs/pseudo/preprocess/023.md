# 023 전처리 의사코드

## 목적
이 문서는 `023.국회 회의록 기반 지식검색 데이터`를 `docs/personal/preprocess/023.md`의 예시 형태 그대로 Lance row로 만드는 절차를 자연어로 설명한다.
이 데이터셋에서 Lance에 저장되는 row는 `messages`와 `content`를 함께 가지며, `FT`와 `PT` 학습은 같은 row를 서로 다른 필드로 사용한다.

## 고정값
구현할 때는 아래 값을 그대로 사용한다.

1. `source`는 `"023.국회 회의록 기반 지식검색 데이터"`로 둔다.
2. system 문장은 `"당신은 국회회의록 기반으로 대답을 하는 위원이야. 질문에 대해서 사실 근거에 기반해서 대답해줘."`로 둔다.
3. train 입력은 `data/korean_raw/023.국회 회의록 기반 지식검색 데이터/3.개방데이터/1.데이터/Training/02.라벨링데이터/**/*.json`에서 찾는다.
4. val 입력은 `data/korean_raw/023.국회 회의록 기반 지식검색 데이터/3.개방데이터/1.데이터/Validation/02.라벨링데이터/**/*.json`에서 찾는다.
5. `split`은 경로 기준으로 `train`, `val`만 사용한다.
6. `data_type`은 `"dialog"`로 둔다.

## 입력 파일 탐색 절차
구현할 때는 아래 순서를 따른다.

1. train glob으로 파일을 모두 찾는다.
2. 파일 경로를 정렬한다.
3. 파일명이 `LAB_`로 시작하는 파일만 남기고 나머지는 제외한다.
4. 각 파일에 `split="train"`을 붙인다.
5. val glob으로 파일을 모두 찾는다.
6. 파일 경로를 정렬한다.
7. 파일명이 `LAB_`로 시작하는 파일만 남기고 나머지는 제외한다.
8. 각 파일에 `split="val"`을 붙인다.
9. 두 목록을 합쳐 입력 파일 목록으로 사용한다.

## 파일 처리 절차
파일 하나를 처리할 때는 아래 순서를 따른다.

1. JSON 파일을 읽는다.
2. 파싱에 실패하면 파일 단위 품질 이벤트를 남기고 다음 파일로 넘어간다.
3. 최상위 `context`, `question.comment`, `answer.comment`를 읽는다.
4. `context`가 문자열이 아니면 이 레코드는 버리고 품질 이벤트를 남긴다.
5. `question`이 객체가 아니거나 `question.comment`가 문자열이 아니면 이 레코드는 버리고 품질 이벤트를 남긴다.
6. `answer`가 객체가 아니거나 `answer.comment`가 문자열이 아니면 이 레코드는 버리고 품질 이벤트를 남긴다.
7. `context`, `question.comment`, `answer.comment`에 대해 좌우 공백을 제거한다.
8. 좌우 공백 제거 후 `context`가 빈 문자열이면 이 레코드는 버린다.
9. 좌우 공백 제거 후 `question.comment` 또는 `answer.comment`가 빈 문자열이면 이 레코드는 버린다.
10. `context_learn`과 `context_summary`는 기본 규칙에서는 사용하지 않는다.

## row 생성 절차
정규화에 성공한 레코드는 아래 형태의 row 하나를 만든다.

1. `data_type`은 `"dialog"`로 둔다.
2. `source`는 고정값을 넣는다.
3. `split`은 입력 파일에서 가져온 값을 넣는다.
4. `content`에는 정규화된 `context`를 넣는다.
5. `messages`는 길이 3 배열로 만든다.
6. `messages[0]`에는 고정 system 문장을 `role="system"`으로 넣는다.
7. `messages[1]`에는 정규화된 `question.comment`를 `role="user"`로 넣는다.
8. `messages[2]`에는 정규화된 `answer.comment`를 `role="assistant"`로 넣는다.
9. `token_count`는 저장 직전에 FT 직렬화 기준으로 계산한다.

## PT 사용 전략
이 데이터셋의 PT 입력은 별도 PT row를 만들지 않고 같은 row의 `content`를 사용한다.

1. PT 학습 시 row의 `content`를 그대로 사용한다.
2. `messages`는 PT 입력 생성에서 사용하지 않는다.

## FT 직렬화와 token_count
`token_count`를 계산할 때는 아래 순서를 따른다.

1. `messages`를 `<|system|>...<|user|>...<|assistant|>...` 형태로 직렬화한다.
2. 직렬화된 문자열을 공통 토크나이저로 인코딩한다.
3. 나온 토큰 수를 `token_count`에 넣는다.

## 품질 이벤트 기록 방식
품질 이벤트를 남길 때는 최소한 아래 정보를 기록한다.

1. dataset은 `023`
2. split
3. file path
4. record id(`id` 또는 `question_number`)
5. reason code
6. reason detail
7. sample text 일부
8. `skip`, `error` 중 성격

## 구현 체크리스트
1. `content`가 항상 `context`에서 생성되는가
2. `messages`가 항상 `system -> user(question.comment) -> assistant(answer.comment)` 순서인가
3. `context`, `question.comment`, `answer.comment`에 strip을 적용하는가
4. `context_learn`, `context_summary`를 기본 규칙에서 제외했는가
5. `token_count`를 FT 직렬화 기준으로 계산하는가
