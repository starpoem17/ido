# 030 전처리 의사코드

## 목적
이 문서는 `030.웹데이터 기반 한국어 말뭉치 데이터`를 `docs/personal/preprocess/030.md`의 예시 형태 그대로 Lance row로 만드는 절차를 자연어로 설명한다.
이 데이터셋에서 Lance에 저장되는 row 형태는 `FT` 하나뿐이며, `content`는 항상 `null`이다.

## 고정값
구현할 때는 아래 값을 그대로 사용한다.

1. `source`는 `"030.웹데이터 기반 한국어 말뭉치 데이터"`로 둔다.
2. system 문장은 `"당신은 기사를 읽고 제목을 짓습니다. 내용을 요약하고, 사람들의 눈길을 끄는 제목을 작성합니다."`로 둔다.
3. train 입력은 `data/korean_raw/030.웹데이터 기반 한국어 말뭉치 데이터/01.데이터/1.Training/라벨링데이터/**/*.json`에서 찾는다.
4. val 입력은 `data/korean_raw/030.웹데이터 기반 한국어 말뭉치 데이터/01.데이터/2.Validation/라벨링데이터/**/*.json`에서 찾는다.
5. 본문 문장 결합 구분자는 공백 하나로 둔다.

## row 단위
personal 문서의 `title 헤드 하나당 하나의 행` 규칙을 그대로 따른다.
따라서 구현할 때는 아래처럼 처리한다.

1. 파일의 `named_entity` 배열을 순서대로 읽는다.
2. `named_entity` 하나를 기사 1개로 본다.
3. 그 기사 안의 `title[*]` 항목 하나를 row 1개로 본다.
4. 같은 기사에 제목이 여러 개 있으면 제목 수만큼 row를 만든다.
5. 각 row의 `assistant`에는 해당 제목 하나만 넣는다.
6. 각 row의 `user`에는 그 기사의 `content[*].sentence` 전체를 이어 붙인 문자열을 넣는다.

## 파일 처리 절차
파일 하나를 처리할 때는 아래 순서를 따른다.

1. JSON 파일을 읽는다.
2. 파싱에 실패하면 파일 단위 품질 이벤트를 남기고 건너뛴다.
3. 최상위 `named_entity`를 읽는다.
4. `named_entity`가 없거나 배열이 아니면 파일 단위 품질 이벤트를 남기고 건너뛴다.
5. `named_entity`를 처음부터 끝까지 순회한다.

## 기사 정규화 절차
기사 하나를 처리할 때는 아래 순서를 따른다.

1. `content` 배열을 읽는다.
2. `title` 배열을 읽는다.
3. `content`가 없거나 배열이 아니면 이 기사는 버린다.
4. `title`이 없거나 배열이 아니면 이 기사는 버린다.
5. `content[*].sentence`를 순서대로 읽는다.
6. sentence가 문자열이면 좌우 공백을 제거한다.
7. 좌우 공백 제거 후 빈 문자열이 아니면 본문 문장 목록에 넣는다.
8. 최종 본문 문장 목록이 비어 있으면 이 기사는 버린다.
9. 본문 문장 목록을 공백 하나로 이어 붙여 `user` 문자열을 만든다.
10. `title[*].sentence`를 순서대로 읽는다.
11. title sentence가 문자열이면 좌우 공백을 제거한다.
12. 좌우 공백 제거 후 빈 문자열이 아니면 유효한 제목으로 본다.
13. 유효한 제목이 하나도 없으면 이 기사는 버린다.

## row 생성 절차
유효한 제목 하나마다 아래 형태의 row 하나를 만든다.

1. `data_type`은 `"FT"`로 둔다.
2. `source`는 고정값을 넣는다.
3. `split`은 파일 경로 기준으로 넣는다.
4. `content`는 `null`로 둔다.
5. `messages`는 길이 3의 배열로 만든다.
6. 첫 원소에는 system 문장을 넣는다.
7. 두 번째 원소에는 기사 본문 문자열을 `user`로 넣는다.
8. 세 번째 원소에는 현재 제목 문자열을 `assistant`로 넣는다.
9. `token_count`는 저장 직전에 FT 직렬화 기준으로 계산한다.

## PT 사용 전략
personal 문서의 `PT 시에는 ...` 규칙은 Lance에 PT row를 하나 더 저장하라는 뜻이 아니라,
이 FT row를 downstream에서 PT 문자열로 어떻게 변환할지에 대한 규칙으로 해석한다.

구현할 때는 아래 helper를 별도로 둔다.

1. system 문장은 제외한다.
2. `assistant` 제목을 먼저 둔다.
3. 줄바꿈 `\n` 하나를 둔다.
4. `user` 본문을 뒤에 둔다.
5. 최종 문자열은 `제목 + "\n" + 본문` 형식이 된다.

## FT 직렬화와 token_count
`token_count`를 계산할 때는 아래 순서를 따른다.

1. `messages`를 `<|system|>...<|user|>...<|assistant|>...` 형태로 직렬화한다.
2. 직렬화된 문자열을 공통 토크나이저로 인코딩한다.
3. 나온 토큰 수를 `token_count`에 넣는다.

## 품질 이벤트 기록 방식
품질 이벤트에는 최소한 아래를 남긴다.

1. dataset은 `030`
2. split
3. file path
4. 기사 인덱스와 제목 인덱스
5. reason code
6. reason detail
7. sample text 일부
8. `skip` 또는 `error`

## 구현 체크리스트
1. 최종 row가 항상 `FT`인가
2. 최종 row의 `content`가 항상 `null`인가
3. `title[*]` 하나당 row 1개를 만드는가
4. `content[*].sentence`를 공백으로 이어 붙여 `user`를 만드는가
5. system 문구가 personal 문서와 완전히 같은가
6. `PT 시 사용 전략`을 별도 helper로 분리했는가
7. `token_count`를 FT 직렬화 기준으로 계산하는가
