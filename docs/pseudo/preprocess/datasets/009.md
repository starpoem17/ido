# 009 전처리 스도코드

## 목적
`009.전문분야_기술과학_한국어 멀티세션 데이터`를 canonical parquet row로 만들고,
dedup 이후 dataset별 Lance dataset으로 올릴 때 따라야 하는 규칙을 적는다.

## 고정값
1. `source = "009.전문분야_기술과학_한국어 멀티세션 데이터"`
2. `data_usage = "SFT"`
3. `system = "당신은 기술과학 전문 비서입니다. 사용자의 질문에 친절하고 과학적으로 대답합니다."`
4. 입력 경로는 `data/korean_raw/009.전문분야_기술과학_한국어 멀티세션 데이터/3.개방데이터/1.데이터/**/*.json`

## parquet 생성 규칙
1. JSON 파일을 읽고 `sessionInfo[*]`를 session row 단위로 처리한다.
2. `sessionID`가 있으면 `split_key`로 사용하고, 없으면 `file_path + session_index`를 사용한다.
3. `dialog[*].utterance`를 좌우 strip한다.
4. `speaker1 -> user`, `speaker2 -> assistant`로 매핑한다.
5. 빈 utterance가 하나라도 있으면 session 전체를 제외한다.
6. 시작 role이 user가 아니면 제외한다.
7. role 교대가 깨지면 제외한다.
8. 마지막 turn이 user면 마지막 user turn 하나만 제거한다.
9. 마지막 보정 후 assistant turn이 없으면 제외한다.
10. `messages = [system, user, assistant, ...]`로 만든다.
11. `content`는 system을 제외한 user/assistant utterance를 공백 하나로 이어 붙인다.
12. `token_count`는 비워 둔 채 parquet로 저장한다.

## Lance 업로드 규칙
1. minhash dedup 완료 parquet에서 `source == "009.전문분야_기술과학_한국어 멀티세션 데이터"` row만 읽는다.
2. 공통 [docs/pseudo/preprocess/build_lance.md](/Users/nojonghyeon/Documents/GitHub/ido/docs/pseudo/preprocess/build_lance.md) 절차가 이 row를 읽어 `messages` 직렬화, SFT 분할, 최종 `token_count` 재계산을 수행한다.
3. 최종 결과는 source별 shard를 거쳐 하나의 Lance dataset으로 append된다.
