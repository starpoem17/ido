# 020 전처리 의사코드

## 목적
이 문서는 `020.주제별 텍스트 일상 대화 데이터`를 `docs/personal/preprocess/020.md`의 예시 형태 그대로 Lance row로 만드는 절차를 자연어로 설명한다.
이 데이터셋에서 Lance에 저장되는 row는 `messages`와 `content`를 함께 가지며, FT와 PT 학습은 같은 row를 서로 다른 필드로 사용한다.

## 고정값
구현할 때는 아래 값을 그대로 사용한다.

1. `source`는 `"020.주제별 텍스트 일상 대화 데이터"`로 둔다.
2. system 문장은 `"당신은 일상 대화 상대입니다. 사용자의 말에 자연스럽고 친근하게 반응하세요."`로 둔다.
3. train 입력은 `data/korean_raw/020.주제별 텍스트 일상 대화 데이터/01.데이터/1.Training/라벨링데이터/**/*.json`에서 찾는다.
4. val 입력은 `data/korean_raw/020.주제별 텍스트 일상 대화 데이터/01.데이터/2.Validation/라벨링데이터/**/*.json`에서 찾는다.
5. `split`은 경로 기준으로 `train`, `val`만 사용한다.
6. turn 병합 구분자는 공백 하나(`" "`)로 둔다.

## 입력 파일 탐색 절차
구현할 때는 아래 순서를 따른다.

1. train glob으로 파일을 모두 찾는다.
2. 파일 경로를 정렬한다.
3. 각 파일에 `split="train"`을 붙인다.
4. val glob으로 파일을 모두 찾는다.
5. 파일 경로를 정렬한다.
6. 각 파일에 `split="val"`을 붙인다.
7. 두 목록을 합쳐 입력 파일 목록으로 사용한다.

## 파일 처리 절차
파일 하나를 처리할 때는 아래 순서를 따른다.

1. JSON 파일을 읽는다.
2. 파싱에 실패하면 파일 단위 품질 이벤트를 남기고 다음 파일로 넘어간다.
3. 최상위 `info`를 읽는다.
4. `info`가 배열이 아니면 파일 단위 품질 이벤트를 남기고 다음 파일로 넘어간다.
5. `info[*]`를 순서대로 순회하며 각 항목을 레코드 1개로 처리한다.

## 레코드 정규화 절차
레코드 하나를 row로 바꿀 때는 아래 순서를 따른다.

1. `annotations`를 읽는다.
2. `annotations.speaker_type`이 `"1:1"`인지 확인한다.
3. `"1:1"`이 아니면 이 레코드는 버리고 품질 이벤트를 남긴다.
4. `annotations.lines`를 읽는다.
5. `lines`가 배열이 아니면 이 레코드는 버리고 품질 이벤트를 남긴다.
6. `lines`를 처음부터 끝까지 순회한다.
7. 각 line에서 `speaker.id`, `norm_text`, `text`를 읽는다.
8. `norm_text`가 문자열이면 `norm_text`를 사용한다.
9. `norm_text`가 없으면 `text`를 사용하되 `"^\d+\s*:\s*"` 접두어를 제거한다.
10. 최종 turn text를 좌우 공백 제거 후 사용한다.
11. turn text가 빈 문자열이면 해당 turn은 제외하고 `skip_turn` 이벤트를 남긴다.
12. `speaker.id`가 문자열이 아니거나 빈 문자열이면 해당 turn은 제외하고 `skip_turn` 이벤트를 남긴다.
13. turn 순서대로 처음 등장한 speaker를 `user`로 고정한다.
14. 다음으로 등장한 다른 speaker를 `assistant`로 고정한다.
15. 세 번째 speaker가 등장하면 이 레코드는 버리고 품질 이벤트를 남긴다.
16. 정규화된 turn을 `{role, content}` 형태로 임시 배열에 넣는다.
17. 정규화 후 turn 배열이 비어 있으면 이 레코드는 버린다.

## 연속 화자 병합 절차
연속으로 같은 role이 나온 turn은 아래 방식으로 병합한다.

1. 병합 결과 배열을 빈 배열로 시작한다.
2. turn을 순서대로 보면서 이전 turn과 role이 같으면 `이전 content + " " + 현재 content`로 합친다.
3. role이 다르면 새 turn으로 추가한다.
4. 병합 후 첫 role이 `user`가 아니면 레코드를 버린다.
5. 병합 후 마지막 role이 `user`면 마지막 user turn 하나를 제거하고 `fixup` 이벤트를 남긴다.
6. 마지막 user 제거 후 배열이 비었거나 마지막 role이 `assistant`가 아니면 레코드를 버린다.
7. 최종 turn 배열에 `assistant`가 하나도 없으면 레코드를 버린다.

## row 생성 절차
정규화에 성공한 레코드는 아래 형태의 row 하나를 만든다.

1. `source`는 고정값을 넣는다.
2. `split`은 입력 파일에서 가져온 값을 넣는다.
3. `messages`는 새 배열로 만든다.
4. `messages[0]`에는 고정 system 문장을 `role="system"`으로 넣는다.
5. 그 뒤에는 병합된 turn을 순서대로 그대로 넣는다.
6. `content`는 `messages`에서 system을 제외한 user/assistant의 `content`를 원순서대로 공백 하나로 이어 붙인 문자열로 둔다.
7. `token_count`는 저장 직전에 FT 직렬화 기준으로 계산한다.

## PT 사용 전략
이 데이터셋의 PT 입력은 별도 PT row를 만들지 않고 같은 row의 `content`를 사용한다.

1. PT 학습 시 row의 `content`를 그대로 사용한다.
2. `messages`는 PT 입력 생성에서 사용하지 않는다.

## FT 직렬화와 token_count
`token_count`를 계산할 때는 아래 순서를 따른다.

1. `messages`를 `<|system|>...<|user|>...<|assistant|>...` 형태로 직렬화한다.
2. 직렬화된 문자열을 공통 토크나이저로 인코딩한다.
3. 나온 토큰 수를 `token_count`에 넣는다.

## 품질 이벤트 기록 방식
품질 이벤트를 남길 때는 최소한 아래 정보를 기록한다.

1. dataset은 `020`
2. split
3. file path
4. record id(`info[*].id` 또는 `info[*].filename`)
5. reason code
6. reason detail
7. sample text 일부
8. `skip`, `fixup`, `error` 중 성격

## 구현 체크리스트
1. `norm_text`를 우선 사용하고 없을 때만 `text`를 사용하는가
2. 화자 매핑이 "첫 화자=user, 둘째 화자=assistant" 규칙을 따르는가
3. 세 번째 화자가 나오면 레코드를 제외하는가
4. 연속 같은 화자 turn을 병합하는가
5. 마지막 user turn 보정을 수행하는가
6. `content`가 system 제외 user/assistant concat 규칙으로 생성되는가
7. `token_count`를 FT 직렬화 기준으로 계산하는가
