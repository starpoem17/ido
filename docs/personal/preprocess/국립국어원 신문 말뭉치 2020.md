모델이 신문 기사 형식의 긴 문서를 읽는 PT 패턴을 학습할 수 있도록 하는 데이터
원본 JSON의 `document` 안의 요소 하나가 행 하나의 단위가 된다.
이 데이터셋은 PT 전용으로 사용하고 FT용 `messages`는 만들지 않는다.
문자열 필드는 모두 처음과 끝 공백을 strip하여 수집한다.
원본 배포본에는 별도 Training/Validation 분할이 없으므로 split은 모두 `train`으로 둔다.

PT content 생성 규칙
출력하고 싶은 형식은 아래와 같다.

`제목: <기사 제목>`
`내용: <기사 본문>`

원본 샘플 기준으로 기사 제목 역할은 `document.title`이 아니라 첫 번째 유효 `document.paragraph[*].form`에 들어 있으므로, `제목:`에는 첫 번째 유효 `paragraph.form`을 사용한다.
나머지 유효 `document.paragraph[*].form`들은 원순서대로 수집하여 `내용:`에 넣는다.
본문 문단 concat 구분자는 줄바꿈(`\n`) 하나를 사용한다.
최종 `content`는 아래 형식으로 만든다.

`제목: ` + title + `\n내용: ` + body

정규화 규칙
`document.paragraph`가 배열이 아니면 해당 `document`는 제외한다.
각 `paragraph.form`이 문자열이 아니거나 strip 후 빈 문자열이면 해당 문단은 제외한다.
정규화 후 유효한 문단이 하나도 없으면 해당 `document`는 제외한다.
첫 번째 유효 문단을 제목으로 사용한 뒤 남은 본문 문단이 하나도 없으면 해당 `document`는 제외한다.

행 생성 규칙
`source`는 `"국립국어원 신문 말뭉치 2020"`을 사용한다.
`split`은 항상 `train`으로 둔다.
`content`에는 위 PT content 생성 규칙의 결과 문자열을 넣는다.
`messages`는 항상 null로 둔다.
`document.metadata.author`, `publisher`, `date`, `topic`, `original_topic`과 파일 상위 `metadata`는 기본 PT 입력에서 사용하지 않는다.

ex)
{
    "source" : "국립국어원 신문 말뭉치 2020",
    "split" : "train",

    "messages" : null,
    "token_count" : 123

PT 시에는 row의 `content`를 그대로 사용한다.
FT 시에는 이 데이터셋 row를 사용하지 않는다.
