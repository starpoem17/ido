모델이 기사 본문을 읽고 제목을 생성하는 패턴을 학습할 수 있도록 하는 데이터
원본 JSON의 `named_entity[*]` 안의 `title[*]` 요소 하나가 행 하나의 단위가 된다.
`named_entity.content[*].sentence`는 user 본문으로 사용하고, `named_entity.title[*].sentence`는 assistant 제목으로 사용한다.
문자열 필드는 모두 처음과 끝 공백을 strip하여 수집한다.
Training은 train, Validation은 val로 매핑한다.

행 생성 규칙
data_usage는 "SFT"를 사용한다.
system에는 고정 문구 `"당신은 기사를 읽고 제목을 짓습니다. 내용을 요약하고, 사람들의 눈길을 끄는 제목을 작성합니다."`를 넣는다.
messages는 [system, user, assistant] 구조로 저장한다.
user에는 같은 기사의 유효한 `content[*].sentence`를 원순서대로 공백 하나로 이어 붙인 문자열을 넣는다.
assistant에는 현재 `title[*].sentence` 하나를 넣는다.
content는 `assistant 제목 + "\n" + user 본문` 형식으로 저장한다.
content concat 시 본문 문장 구분자는 단일 공백(" ")을 사용한다.

ex)
{
    "source" : "030.웹데이터 기반 한국어 말뭉치 데이터",
    "data_usage" : "SFT",
    "split" : "train",
    "content" : "국산 '탐나는 봉' 한라봉 대신할까?\n감귤과 함께 겨울철 과일로 자리잡은 한라봉. 감귤에 비해 높은 가격을 받을 수 있어 재배하는 가구가 적지 않다. 그런데 한라봉은 토속적인 이름과 다르게 일본에서 온 품종으로 로열티를 지급해야 한다. 일본의 농림성이 육성한 '데코폰'이 국내에서 재배되면서 한라봉이란 이름이 붙은 것이다.",

        {"role" : "assistant", "content" : "국산 '탐나는 봉' 한라봉 대신할까?"}
    ],
    "token_count" : null
}

PT 시에는 row의 content를 그대로 사용한다.
FT 시에는 row의 messages를 직렬화해 사용한다. 직렬화 시에는 <|system|>, <|user|>, <|assistant|> 특수 토큰을 붙인다.
