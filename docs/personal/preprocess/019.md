모델이 법률 문서를 읽고 판결/주장/사실관계를 이해하는 PT 패턴을 학습할 수 있도록 하는 데이터
원본 JSON 한 건이 행 하나의 단위가 된다.
이 데이터셋은 PT 전용으로 사용하고 FT용 messages는 만들지 않는다.
문자열 필드는 모두 처음과 끝 공백을 strip하여 수집한다.
Training은 train, Validation은 val로 매핑한다.

PT content 생성 규칙
아래 필드의 문자열들을 원순서대로 모아 concat하여 content를 만든다.
1. `mentionedItems.rqestObjet`
2. `disposal.disposalcontent`
3. `assrs.dedatAssrs`
4. `facts.bsisFacts`
5. `dcss.courtDcss`
6. `close.cnclsns`
7. `clauseArticle`
8. `comProvision`

각 필드는 배열로 가정하고, 배열 원소가 문자열이면 strip 후 사용한다.
빈 문자열은 제외하고 나머지를 concat한다.
최종 content concat 구분자는 줄바꿈(`\n`) 하나를 사용한다.
8개 후보 필드 중 하나라도 유효한 문자열이 있으면 해당 레코드는 유지한다.
최종 content가 비어 있으면 해당 레코드는 제외한다.

행 생성 규칙
data_type은 "text"를 사용한다.
messages는 항상 null로 둔다.
content에는 위 PT content 생성 규칙의 결과 문자열을 넣는다.
`info`, `concerned`, `org`, `relateLaword`, `qotatPrcdnt`, `acusrAssrs`는 기본 PT 입력에서 사용하지 않는다.
row가 생성된 경우 `skip_field`, `skip_item`은 `fixup`으로 기록하고, `empty_content`만 실제 drop을 뜻하는 `skip`으로 기록한다.

ex)
{
    "source" : "019.법률, 규정 (판결서, 약관 등) 텍스트 분석 데이터",
    "split" : "train",
    "content" : "피고는 원고에게 72,948,240원 및 ...\n제1심판결 중 피고에 대하여 원고에게 14,589,648원 및 ...\n피고는 요금수납원이 피해자에게 위험신호를 보냈을 뿐 ...\n이 법원의 판결이유는 다음과 같이 고치는 외에는 ...\n이 사건 사고는 앞서 본 피고 소속 요금수납원의 과실과 ...\n그렇다면 원고의 청구는 위 인정범위 내에서 이유 있어 인용하고 ...",
    "messages" : null,
    "token_count" : 123
}

PT 시에는 row의 content를 그대로 사용한다.
FT 시에는 이 데이터셋 row를 사용하지 않는다.
