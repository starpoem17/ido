모델이 책/정보 문어 문체의 긴 문서를 읽는 PT 패턴을 학습할 수 있도록 하는 데이터
원본 JSON의 `document` 안의 요소 하나가 행 하나의 단위가 된다.
이 데이터셋은 PT 전용으로 사용하고 FT용 `messages`는 만들지 않는다.
문자열 필드는 모두 처음과 끝 공백을 strip하여 수집한다.
원본 배포본에는 별도 Training/Validation 분할이 없으므로 유효 `document` row를 self-split하여 `train:val = 90:10`으로 구성한다.

PT content 생성 규칙
출력하고 싶은 형식은 아래와 같다.

`제목: <document.metadata.title>`
`내용: <document.paragraph.form concat>`

원본 샘플 기준으로 제목은 `document.metadata.title`에 들어 있으므로 `제목:`에는 `document.metadata.title`을 사용한다.
유효한 `document.paragraph[*].form`들은 원순서대로 수집하여 `내용:`에 넣는다.
본문 문단 concat 구분자는 줄바꿈(`\n`) 하나를 사용한다.
최종 `content`는 아래 형식으로 만든다.

`제목: ` + title + `\n내용: ` + body

정규화 규칙
`document.metadata.title`이 문자열이 아니거나 strip 후 빈 문자열이면 해당 `document`는 제외한다.
`document.paragraph`가 배열이 아니면 해당 `document`는 제외한다.
각 `paragraph.form`이 문자열이 아니거나 strip 후 빈 문자열이면 해당 문단은 제외한다.
정규화 후 유효한 문단이 하나도 없으면 해당 `document`는 제외한다.

split 규칙
canonical split key는 `document.id`, 없으면 `{file_stem}:{document_index}`를 사용한다.
split 할당은 `sha256(source + "\t" + split_key)` 기준으로 정렬한 뒤 앞 `floor(n * 0.9)`개를 train, 나머지를 val로 둔다.
`n == 1`이면 유일한 row는 train으로 둔다.
split 계산은 정규화 후 최종 row 후보 집합 기준으로 수행한다.

행 생성 규칙
`source`는 `"국립국어원 문어 말뭉치"`를 사용한다.
`data_usage`는 `"PT"`를 사용한다.
`split`은 위 split 규칙의 결과값을 사용한다.
`content`에는 위 PT content 생성 규칙의 결과 문자열을 넣는다.
`messages`는 항상 null로 둔다.
`document.metadata.author`, `publisher`, `date`와 파일 상위 `metadata`, `paragraph.id`는 기본 PT 입력에서 사용하지 않는다.

ex)
{
    "source" : "국립국어원 문어 말뭉치",
    "data_usage" : "PT",
    "split" : "train",
    "content" : "제목: 폭력과 존엄 사이\n내용: 들어가는 말\n잠깐 내린 눈\n우리가 보는 것은 피와 살로 고동치는 삶의 어느 한 부분이다.",
    "messages" : null,
    "token_count" : null
}

PT 시에는 row의 `content`를 그대로 사용한다.
FT 시에는 이 데이터셋 row를 사용하지 않는다.
