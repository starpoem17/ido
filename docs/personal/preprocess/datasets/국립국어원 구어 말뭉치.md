모델이 실제 구어 발화 흐름을 PT 패턴으로 학습할 수 있도록 하는 데이터
원본 JSON의 `document` 안의 요소 하나가 행 하나의 단위가 된다.
이 데이터셋은 PT 전용으로 사용하고 FT용 `messages`는 만들지 않는다.
문자열 필드는 모두 처음과 끝 공백을 strip하여 수집한다.
현재 확인한 배포본은 별도 Training/Validation 분할이 없으므로 split은 모두 `train`으로 둔다.

PT content 생성 규칙
출력하고 싶은 형식은 아래와 같다.

`<utterance.form 1>\n<utterance.form 2>\n<utterance.form 3>\n...`

원본의 `document.utterance[*].form`을 원순서대로 수집하여 `content`로 만든다.
발화 concat 구분자는 줄바꿈(`\n`) 하나를 사용한다.
빈 `form`은 제외하고 유효한 `form`만 이어 붙인다.
최종 `content`는 유효한 `document.utterance[*].form`들을 줄바꿈 하나로 이어 붙인 문자열이다.

정규화 규칙
`document`가 배열이 아니면 해당 JSON은 제외한다.
각 `document.utterance`가 배열이 아니면 해당 `document`는 제외한다.
각 `utterance.form`이 문자열이 아니거나 strip 후 빈 문자열이면 해당 발화는 제외한다.
정규화 후 유효한 발화가 하나도 없으면 해당 `document`는 제외한다.
발화 순서는 원본 순서를 그대로 유지한다.

행 생성 규칙
`source`는 `"국립국어원 구어 말뭉치"`를 사용한다.
`data_usage`는 `"PT"`를 사용한다.
`split`은 항상 `train`으로 둔다.
`content`에는 위 PT content 생성 규칙의 결과 문자열을 넣는다.
`messages`는 항상 null로 둔다.
`document.metadata.title`, `author`, `publisher`, `date`, `topic`, `speaker`와 파일 상위 `metadata`, `utterance.original_form`, `speaker_id`, `note`는 기본 PT 입력에서 사용하지 않는다.

ex)
{
    "source" : "국립국어원 구어 말뭉치",
    "data_usage" : "PT",
    "split" : "train",
    "content" : "안녕하세요?\n티비에스 기적의 티비 상담받고 대학가자 아나운서 조현아입니다.\n대입 수험생을 위한 수시 집중 상담으로 진행되는 기적의 티비 상담받고 대학가자 오늘은 고려대 생명공학부와 한양대 신소재공학부 진학을 희망하는 학생의 진학 상담 준비돼있습니다.",
    "messages" : null,
    "token_count" : null
}

PT 시에는 row의 `content`를 그대로 사용한다.
FT 시에는 이 데이터셋 row를 사용하지 않는다.
